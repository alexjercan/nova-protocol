1. Summary

SOURCE
  • The player's rotation command is a full world quaternion, not an aim direction. Mouse or right stick drives a camera "point rotation" rig with local yaw and pitch only; its output is slewed into the Controller section command, and a 3-axis PD loop applies torque to the hull.
  • The command already has a roll degree of freedom. The PD clamps acceleration per principal axis and turns the hull about any axis, roll included. Nothing in the player input path writes roll.
  • The chase camera takes its up vector from the same rig, so rolling the rig rolls the view; the autopilot and scripted align turn by shortest arc from the previous command, so a pilot roll persists through maneuvers.
  • Q and E are the free keyboard pair in the Flight context (R, F, C are runtime section defaults). The gamepad has no free button in the Flight context.
PROPOSED Add a roll rate to the normal camera rig's integrator (roll about the rig's forward axis). Everything after the rig - slew, PD, torque, docked wrench, controller stacking, adrift freeze - is reused unchanged. No RCS read or write. Recommendation for the seat: option A (roll the rig), see section 5. Binding choice stays with the owner.

// nova_gameplay::transform::point_rotation (owning crate first)
// either widen the existing input ...
pub struct PointRotationInput(pub Vec3);   // x yaw, y pitch, z roll (rad this frame)
// ... or add a sibling the same integrator reads
pub struct PointRollInput(pub f32);        // rad this frame, about rig forward

fn compute_point_rotation(state, input) -> PointRotationState {
    // existing yaw, pitch ...
    if roll != 0.0 {
        let q = Quat::from_axis_angle(state.forward, roll);
        state.right = (q * state.right).normalize();   // forward unchanged
    }
}

7. Physical roll capability

SOURCE
  • The PD error is the full axis-angle of command * hull^-1, so a pure roll error gives an axis along the hull nose (pd_controller.rs:187-198).
  • The clamp is per principal axis in acceleration units, so roll gets the same authored angular acceleration as pitch and yaw; torque = acceleration x principal inertia (pd_controller.rs:200-219). A long hull has its smallest inertia about the nose, so roll needs the least torque for the same rate.
  • The command slew caps the geodesic step, so roll and yaw/pitch share one turn-rate budget per frame (guidance.rs:362-370).
  • Stacked controllers share one hull-wide ceiling (controller_section.rs:200-230).
SOURCE Existing PD tests already drive roll about the long axis: a 1.5 rad/s roll despins with a tracking or frozen command, and under saturating authority (pd_controller.rs:784-822, 884). They prove roll damping, not a commanded roll to a new angle. Not run in this session.
NOT MEASURED No run in this session drove a rolled command. Roll rate and settle time on base hulls are unknown until a spike or the implementation runs. The claims above are source-derived.
