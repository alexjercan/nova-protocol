20260826-162503 One owner for the keyboard 502fe14a

Every key system used to guard itself with a hand-kept denial list, and the lists had drifted apart. nova_ui::input_mode replaces them with an arbiter and two rules.

  • ruleA VERB runs in InputMode::Normal alone. A MODE'S OWN system runs with owns_or_enters(mode) — its mode and Normal, because the key that opens a mode is pressed before the mode exists.
  • orderThe enum's declaration order IS the exclusivity order: Normal < Browse < Insert < Bind. Who wins a contested frame is one enum away rather than a rule per pair.
  • claimModes are claimed, not set. Whoever holds the state writes a ClaimKeyboard each frame; InputModeSystems keeps the greatest; a mode ends by going quiet. No release to forget.
  • deletedrebind_armed; typing_into_a_field and all nine call sites; escape_backs_out's own rebind.target.is_some() check and its two .before() edges.
New range system_input_modes presses, per mode, the one key two owners would both answer, and reads the NEGATIVE after a bounded settle — there is no event for a key that went nowhere. Four invariants on the roster. Mutation-checked live: dropping the Normal gate from delete_key fails the Insert beat, exit 101.

R2.1 The scrub's travel and its snap grid come from two different lookups Blocker

The row's name is the grip. Drag it and the number moves. That is the control the UI task was written to add, and it is the answer the task gives to NaN — a number reached by dragging is the old number plus a delta, so it cannot be one. The gesture works. The arithmetic under it does not.

on_inspector_drag multiplies the frame's pixels by the step the ROW declared, handed to each grip as InspectorDrag(row.nudge). For a pose row that is POSE_STEP, 0.05. Then nudge_field re-derives a step of its own — from the WRITE path, which for an axis box ends at PathStep::Field("x"). No FieldSpec is named "x" or covers it, so the lookup misses and the grid falls back to FREE_STEP, 0.1.

crates/nova_editor/src/inspect.rs:1186two lookups, one gesture
let by = drag.delta.x * grip.0;        // the ROW's step: 0.05
...
let spec = field_spec(path);           // path ends at Field("x") -> None
let step = spec.map_or(FREE_STEP, |spec| spec.step);   // 0.1
let mut moved = snapped(held.value + f64::from(by), step, held.whole);

0.05f32 / 0.1f32 is exactly 0.5, so every step lands precisely on a half-grid point, and f64::round is half-away-from-zero. The value is then written back as TEXT and parsed again as an f32, which is what makes the result depend on where the node happens to sit. Reproduced over the exact chain, one logical pixel per event:

Start x1 px/event, dragged rightWhat the builder sees
0.0, 0.05, 0.10.1 → 0.2 → 0.3 → 0.4moves at double the declared step
0.6, 1.0, 2.5, 3.00.7 → 0.7 → 0.7stalls after one step, or never moves
3.14159, 12.753.2 → 3.3 → 3.3one or two steps, then stalls
any, at 0.05 grid3.05 → 3.10 → 3.15what the declaration promises
Why this is a blocker and not a major It is not confined to the axis rows. CursorMoved.position is documented in LOGICAL pixels and bevy_picking derives Drag::delta from it, so at scale factor 2 a one-physical-pixel mouse move is a 0.5 delta — half the grid for every row, scalars included. Radius at 0.5 px/event does not move over 200 events. The panel's numbers stop scrubbing on exactly the display class the other half of this same range was written to support.

The same split reaches check_floor, which also looks up the axis path — so a Limit::AtLeast declared on a vector field never reaches its components. Nothing depends on that today; it is a trap set for the first bounded Vec3.

Why the proof could not see it system_field_controls scrubs radius — a scalar, the one row where both lookups resolve to the same FieldSpec and the defect cannot appear. It also teleports the cursor 40 px in a single move_cursor, which is one drag event: the one cadence that works. The two unit tests do the same. A control whose failure is a slow gesture needs a proof that moves slowly.

Four of the six lanes found this independently. Two rated it major on the pose rows alone; the lane that carried the HiDPI reach rated it blocker. That is the rating here, because with the scale factor included it stops being a wrong step size on one row and becomes a control that does not work across the panel.

R2.6 Every scrub frame rebuilds the object it is editing Major

Two findings from two lanes that only mean something together.

EditTargets::edit takes objects.get_mut(..), which marks ObjectNode changed whether or not the value moved — and whether or not the edit was refused. drop_edited_views watches Changed<ObjectNode> and despawns the body; sync_object_views respawns it the same frame, minting a fresh mesh asset, a fresh material and a fresh collider. Nothing is cached. Drag an asteroid's Radius for two seconds and that is about 120 of each, with their uploads. On a spaceship node it is the whole multi-section hull, per frame.

drop_edited_views predates this range, and its docstring names the assumption that broke:

crates/nova_editor/src/node.rs:950the assumption
A node's view is built ONCE ... because until the inspector
existed nothing could change a config that already had a body.

The scrub turned one commit per typed edit into one per frame. On its own that is a frame cost in the editor. Put it next to R2.1 and it is worse than that: at one pixel per event the value does not move, and the hull is rebuilt every frame of a gesture that changes nothing. The slower and more careful the drag, the more work it does and the less it achieves.

Unmeasured, and honestly so. No probe range drives a held drag, so no capture would have shown it — the same gap that hid R2.1.

R2.2 · R2.4 · R2.7 · R2.8 What the new systems did not reach Major

The arbiter and the anchor loop both do what they were built to do. Each was adopted by the code that could adopt it, and each has a consumer that could not be.

R2.2
Bind mode does not take WASD off the editor camera. The free-fly rig is bevy_enhanced_input's, so no run condition reaches it; it is removed by three systems keyed on their own state, none of which reads EditorRebind or InputMode. Arm a rebind on a thruster and press W — the most natural thruster binding there is — and W binds while the camera flies forward, so the part the chip points at slides off screen mid-gesture. Insert and Browse are both parked. Bind, the most exclusive mode there is, is not. The task body and the arbiter's own docstring both say otherwise.
R2.7
The key legend advertises keys Bind has taken. sync_key_legend keys its hints on the tool and whether you are inside a ship, so a rebind changes only the last cell. The legend still reads Bksp leave while backspace_steps_out is gated off and apply_section_rebind captures every key but Escape. Press it and Backspace becomes the thruster's fire key. config.rs:348 states the contract this breaks: "the keys that do nothing in the current mode are not listed".
R2.8
Ctrl+S goes quiet under the parts gallery, and nothing can say so. Browse swallowing everything but its own exit is the shape the task chose, and the decision is recorded. What is not recorded is that the gallery is full-screen at GALLERY_Z = 20 and the status line sits at FOOT_Z = 15, so the one surface the editor speaks through is covered. A refusal could not be shown even if one were written, and there is no unsaved-changes guard anywhere.
R2.4
hang_at clamps an anchor that is outside the viewport into it. None of the three sites it replaced clamped. Camera::world_to_viewport errors only past the near and far planes — there is no x/y range check — so a node beside the viewport returns Ok with out-of-range coordinates and the callers hide only on Err. A nameplate for a ship framed out of view now stands on the rail, labelling a ship that is not on screen. And in keybind.rs, clear_of lifts colliding chips and records the UNCLAMPED spot, so a pile keeps walking above the viewport and every chip clamps to y = 0 — landing on one pixel row, the single outcome clear_of exists to prevent. The leaders still start from the unclamped point, so they no longer meet their chips.
R2.5 · R2.9 · R2.10 The panel tells the truth late, or not at all Major
R2.5
A refused box is excluded from the repaint forever. TextFieldError is inserted and removed in one place, on a typed submit; sync_inspector repaints Without<TextFieldError>; the scrub neither writes through it nor clears it. Type -5 into a radius and get refused, then drag that row's name: the radius moves 3 → 5, the rock grows on the stage, and the box still reads -5 in red with min 0 beside it. The only exits are a successful typed submit into that same box, or selecting another node.
R2.9
Empty and unsigned optionals wear grips that can only refuse. walk_option builds the row off the payload TYPE, so a field holding None still gets a step and a grip. On the stock rock's first screen, Mass reads none and says "empty" on every drag event; Seed is an Option<u32> declared Limit::Free, so it walks 3, 2, 1, 0 and then says "not a u32". Both contradict this range's own decision that a scrub arrives at a floor, and both show a Rust type name to a builder where EditorSays::refuse asks for the way out.
R2.10
The player wiki still describes the pre-v0.12.0 editor. It sends the reader to a rail row named Parts that does not exist and a Tools block that does not exist, and lists none of Del, Ctrl+S, F, Backspace or F5. This range then made two of those inert under the gallery. Neither the wiki nor the creator docs mention the Inspector at all, so the scrub gesture and its units are documented nowhere. Most of the rot landed earlier in the cycle; this is the last range before release.
R2.3 The width the task nominated is the width that breaks Major

The UI task's Done-when names a wide and a narrow landscape size, and picks 760x600 as the narrow bound. system_ui_scale runs it. At that size the Ship menu button is drawn on top of the Play button.

Top Bar Left is flex_basis: px(0), flex_grow: 1.0, min_width: px(0), with no flex_shrink and no clip, so it squeezes below the natural width of EDITOR plus five menu buttons and its children overflow. The breadcrumb wrapper on the other side got Overflow::clip() for exactly this reason. The left column never did.

The gap this exposes The range ran 760x600 and asserted a number there — the chip's gap and lead, both correct. Nobody looked at the frame. A range that measures one element at a size can pass while the rest of the screen at that size is broken, which is why the feel lane is the only one that found this and why it needed a rendered run to do it.
R2.11–25 Fifteen minors Minor

Three of these are worth reading on their own. The rest are in tasks/20260826-162500/REVIEW.md.

R2.11
The NOVA OS blip cull inverted. Before layout, inverse_scale_factor() is 0 — this repo documents that itself — so the new unit conversion collapses the panel size to zero AND every projected point to Vec2::ZERO, which then PASSES p.x >= 0.0 && p.x <= size.x. Previously the projection kept physical coordinates and the same filter rejected them. "Cull every blip" became "stack every blip in the corner, visible", for one frame each time the map opens.
R2.13
A beat in the new range cannot reach the field it credits. press_key writes ButtonInput<KeyCode> alone, while text_field_keyboard reads MessageReader<KeyboardInput> — which is why the Escape beat presses both halves. So the Insert beat's Delete never arrives: it proves no verb answered, and its log line "the field took Delete" describes something that did not happen. Gate the field on a mode it can never hold and the beat, its assert and its outcome: marker all stay green.
R2.12
The mode resolves one frame after the state that defines it. declare_editor_keyboard_owner runs in PreUpdate off state that Update writes, so on the frame a rebind is armed the mode is still Normal — and the ordering edge that used to cover this was deleted as part of the same task. Both escape_backs_out and apply_section_rebind run in that frame, so one Escape can spend two rungs. It needs a click-release and an Escape inside the same ~16 ms, which is why it is a minor and not more.

The remaining twelve: a gizmo cache keyed on a scale nothing can change; a nudge that writes when the value did not move; a per-row allocation in curate whose obvious fix would change behaviour; a dead guard left on one verb; a comment that states the arbiter's resolution rule backwards; nameplates that pile where chips do not; the colour picker overlapping the rail at 760 px; the key legend wrapping to five rows over a narrow stage; three documentation chapters the range invalidated; duplicated helpers across the two new ranges; two single-caller constructors; and a docstring welded to the wrong item.

  • heldThe Escape ladder, rung by rung: each is owned by one mode, and just_pressed clearing in PreUpdate stops a rung being answered twice — except on the arming frame (R2.12).
  • heldNo format, no runtime string id, no generated file changed. Wasm and default-features checks clean. Changelog correct against v0.11.0. Three ranges green, catalog_drift 2/2, nova_ui 48 and nova_editor 319 lib tests pass.

— Where it stands Request changes

Request changes on R2.1 alone.

It is the control the UI task exists to add, it fails silently, its failure depends on where the node happens to sit, and it gets worse on exactly the displays the other half of the same range was written for. The fix is small — pass the step the grip already carries into nudge_field, so one number drives both the travel and the snap, and accumulate sub-step deltas rather than discarding a move that rounded away.

R2.2 and R2.7 are one gap seen twice: the arbiter covers the systems it can gate, and the two things it cannot — an external input rig, and a legend that reads state directly — were not brought along. R2.3 is the responsiveness half missing its own Done-when at the width that task nominated, because the range asserted a number at that size without looking at the frame.

Nothing has been changed in response to this round. The findings are recorded at tasks/20260826-162500/REVIEW.md, numbered R2.1 to R2.25, and fixing is a separate step.
