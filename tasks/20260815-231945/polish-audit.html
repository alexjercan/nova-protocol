The reported bug, root-caused

"When a section dies and gets split from the ship, its material resets to the pristine one." Confirmed, and it is two defects stacked.

BUG Wrecks reset to pristine — the grader reads a dead section as an undamaged one

  1. Damage zeroes the section's Health; the destroy cascade fires.

    integrity/health.rs:145-150 → integrity/core.rs:179-196

  2. detach_destroyed_body spawns the wreck piece, reparents the section's mesh children onto it — materials intact, exactly as designed — then despawns the section entity.

    integrity/explode.rs:326-344, :357-361, :373

  3. The meshes still carry SectionCracks { section } pointing at the despawned entity. Next Update, the damage lookup misses and map_or(0.0, …) reads the miss as damage 0.0.

    damage_cracks.rs:428, :434

  4. Bucket 0 means "healed": the pristine source material — held as a strong handle precisely so this swap always works — goes back on, and the cracked material comes off.

    damage_cracks.rs:443-450, source handle :158-166

  5. Permanent: nothing ever removes SectionCracks, and the re-mark path excludes meshes that already carry it. The wreck stays textbook-clean for its whole 30 s life.

    damage_cracks.rs:324-336; explode.rs:342 (TempEntity 30.0)

The module doc claims the opposite behavior ("the cracked material is also what a wreck leaves with", damage_cracks.rs:7-8) and no test covers a despawned section. The codebase already contains the correct pattern for this exact orphan case: the thruster plume grader reads a missing section as "dead drive — plume out" (thruster_section.rs:615-621). Cracks makes the opposite choice with the same 0.0.

Fix shape: on detach, latch the wreck's meshes at their last bucket — or force the top bucket, which reads as charred wreckage — and remove or retarget SectionCracks so the per-frame grade loop stops iterating dangling entities. Add the missing wreck-material test.

BUG The burnt tier is unreachable even before the reset

The killing damage lands in FixedPostUpdate and the whole destroy cascade completes in the same command flush — but derive_damage_level and the crack grader run later, in Update. The section is despawned before the final damage value is ever graded, so the wreck's last real bucket is whatever the previous frame reached. The shader's burnt term needs damage ≥ 0.78, which only buckets 6-7 hit — so a section killed from above ~22% health never renders burnt at all, and a one-shot kill leaves a fully pristine wreck. BURNT_COLOR's own comment describes a state the pipeline cannot currently produce.

rounds.rs:109-113 · erosion.rs:80-107 · section_cracks.wgsl:59-63 · damage_cracks.rs:94-96

Light & atmosphere

The single largest visual lever in the game is here: the scene has authored three-point rigs sitting on top of unconfigured engine defaults.

  • POLISHNo image-based lighting exists — the skybox lights nothing

    Zero uses of any environment-map light. The 4096 cubemap is backdrop only, and hull styles are authored near-dielectric (metallic 0.0-0.15) — consistent with, and likely a workaround for, real metal rendering black without IBL. Bevy 0.19 ships GeneratedEnvironmentMapLight, which derives IBL from the existing skybox handle; the insertion point is one place.

    lifecycle.rs:253-266 · base.content.ron:15,26,327,338,563,574 · shell_skin.rs:928

  • BUGAmbient light is the Bevy default, contradicting the design

    Nothing sets ambient, so a flat white 80-lux wash sits under every authored rig — while the code claims "a scene that authors nothing renders black". One line to fix, then the authored lights are the only lights.

The numbers the game already knows

Exactly nine numeric readouts exist in flight. The simulation computes far more, every frame, and throws it away. Ranked promotion candidates — each with its authoritative, already-running source:

  1. Own-ship integrityHUD

    aggregate_ship_health writes a whole-ship Health to the root every frame — and there is no own-ship HP element in the HUD at all. Only the locked target gets a bar.

    sections/integrity.rs:623, :706

  2. Turn rate, and why it is what it isHUD + OS

    ship_turn_rate() is consumed every frame by input slew; AttitudeEnvelope knows the ceiling and AttitudeLimit::label() knows the reason ("torque-limited" / "structure-limited"). None is a first-class ADRIFT state. Written "for a build screen that has to say WHY a number is what it is" — flight deserves the same sentence.

    guidance.rs:306-322 · attitude.rs:27-121

  3. Time-to-intercept on the lead pipHUD

    lead_intercept_point() solves the intercept time t and returns only the point. The TTI chip is free.

    turret_section/aim.rs (lead_intercept_point)

  4. On-target angleHUD

    muzzle_aim_error() runs per tick with a ~0.92° on-target threshold — a firing-solution readout already computed.

    aim.rs:47-54

  5. Brake distance and flip dataHUD

    ManeuverTelemetry.brake_accel carries its own doc: "No HUD instrument reads this yet." The arrival curve v = √(2·a·margin·d) gives brake distance.

    flight/state.rs:210 · guidance.rs (arrival_speed_limit)

  6. Lock-drop reasonComms

    CombatLockDropped { reason, idle_secs } is a fully-formed diagnostic the player never sees — TargetGone, OutOfRange, AllegianceFlip, IdleDecay. An ideal comms/log line.

    targeting/state.rs:264-284

  7. Rated max speedHUD

    FlightSpeedCap with its soft taper is a genuine "rated velocity" the player cannot currently see.

    flight/state.rs:40 · manual.rs:83-88

  8. Gravity magnitude and SOIOS

    GravityWell { mu, body_radius, soi_radius } — surfaced today only as a direction sphere. Magnitude and SOI distance are free, and exactly the sciency register the game wants.

    gravity.rs:57-89

  9. Torpedo armed stateHUD

    TorpedoArming.is_armed() exists; point-blank duds are currently unexplained to the player. Gameplay legibility, not just flavour.

    torpedo_section/mod.rs:608

Two omissions are deliberate and predate this round: closing speed was cut from the destination readout after playtest, and exact ammo counts are pips-only by written policy. Don't steamroll them — route those numbers to NovaOS instead (next section). Implementation notes: the scenario readout strip (nova_hud/src/readout.rs) is the cheapest existing numeric surface, and the chip recipe is nova_ui::hud::chip_node + units + screen_indicator + HudContextGate. nova_info, despite the name, is only the version string.

The terminal

14 commands 5 capabilities are terminal-only 2 apps, launchable only by typing ~0.8 s first-open boot hard-pauses the game hides the entire HUD gamepad can open it, cannot launch apps

Terminal-only today: autopilot to a contact, section repair/reload, per-section rebinding, the full flight log, the detailed objective list. Known defect: backquote both types into the prompt and cycles HUD visibility (hud_cinematic is Context::Always, nova_hud/src/lib.rs:406-411).

CALL Keep it. The terminal is the identity, not the gimmick.

The whole UI already speaks NovaOS — phosphor chips, CRT loading screens, the menu footer. What makes it feel "out of context" is not that you type; it is that the game stops and the HUD vanishes, so using the ship's computer feels like leaving the ship. Close the gap between HUD and terminal; don't retire either.
  • 1 · Own the pause, keep the world

    Opening the terminal is a tactical pause — fiction-friendly, the pilot looks down at the second seat. Keep it, but dim the HUD instead of hiding it, so the fight you paused stays visible around the screen.

  • 2 · Apps without typing

    MAP / SHIP / LOG / HELP as clickable function keys on the casing chin, and a gamepad app row. enter_app already exists with no production caller. Typing stays the power path; commands stay the fiction.

  • 3 · An eng app — the nerd numbers' home

    The editor's stat block (Turn / Mass / Thrust / HP / Parts + the limit note) rendered live, plus per-section HP, the damage model, gravity, envelope ceilings. This answers the sciency ask and makes the terminal genuinely useful: the HUD gets glanceable chips, NovaOS gets depth. The two deliberate HUD omissions — closing speed, exact ammo — belong exactly here.

  • 4 · Echo results out

    A command's outcome should leave a trace on the HUD after close. map goto already does (the AP chip); make that the pattern.

  • 5 · Docking is the payoff

    The stations task (20260824-125943) needs an interaction surface. NovaOS pages — DOCKING, TRADE — make stations run the same operating system the ship does. The terminal stops being a side feature and becomes the game's interaction OS.

  • 6 · Sweep the frictions

    The backquote conflict; Ctrl-A/E/U/K (swallowed but unimplemented); Home/End; click-to-position; boot skip on first keypress.

Distinct from 20260827-120347 (the CSGO-style console): that is out-of-fiction tooling, overlap today is essentially zero, and it should stay that way — though the console can reuse nova_os::shell's UI-free matcher.
