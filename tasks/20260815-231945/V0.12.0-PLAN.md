## Release theme

A stable editor with a node model: build a ship as a scene, enter it to edit,
exit into a world you can lay out around it, save, and play it. Prefab
stamping is cut from this release; the node graph still lowers to prototype
references. Plus: the game as a drivable process, scenario-language
primitives, a real settings menu, new thruster art including multi-cell
drives, and a coherent vacuum VFX direction.

## Decisions taken (owner, 2026-08-24)

1. **The node graph is editor-internal and lowers to the existing flat
   ScenarioConfig RON.** No format break. Prefab = prototype reference.
2. **Settings scope: tabs + keyboard/gamepad rebinding only.** Gamepad menu
   navigation and the mobile virtual pad stay backlog.
3. **Multi-cell sections (3x3x1, 5x5x3) are a v0.12.0 deliverable** - amended
   after the content audit to spike-first INSIDE the release: the WFC
   representation and per-cell exits are real design forks
   (`CONTENT-AND-ART.md` section 2.6), so the task runs spike -> implement
   with an explicit gate, not feature-first.

## The architecture the research converged on

Every lane independently arrived at the same shape:

- **The editor saves a mod bundle, not a bare scenario.** A `*.content.ron`
  file is already `Vec<Content>`; the editor writes user-built ship designs as
  `Content::Ship` prototypes and the world as `Content::Scenario` whose
  instances are `ShipSource::Prototype` references. Editing a design then
  propagates to every instance through the reference - Godot semantics in the
  editor, copy-free RON on disk, zero new format. "Export my ship" falls out.
- **Instance ids are minted literals.** Each stamped instance gets a
  user-visible literal id at creation (`corvette_1`), stored in the document,
  never re-derived at save (Source-engine fixup lesson; keeps `content lint`
  decidable and diffs byte-stable).
- **Re-lift by convention, no sidecar in v0.12.0.** OnStart
  `SpawnScenarioObject` handlers are layout; everything else is logic. Sort
  all maps before serialising (the current lowering is HashMap-ordered).
  Hand-written mods open READ-ONLY in the editor - a serde round-trip
  destroys their comments, and the ledger campaign is the best authored
  content the project has.
- **Property-level overrides only** (`ShipSectionModification` already
  exists); no structural overrides inside an instance in v0.12.0 - that is
  the documented data-loss source in both Godot and Unity. If needed, offer a
  one-way "make local" (inline the sections).
- **The state-wait fix is the node model's first slice.** Exposing "is there
  a solved placement under the pointer" (20260824-011329) fixes the CI flake
  AND establishes the premise the whole editor rework rests on: editor state
  is inspectable data.
- **The bindings registry comes before the names.** A resource owning
  per-action (name, keyboard binds, gamepad binds) that the flight rig is
  BUILT FROM solves the settings menu (no rig exists in the main menu),
  rebinding, persistence, and the dispatcher in one structure. Naming without
  it leaves reference.rs alive.

## What the research killed

- The old epic's phased plan: phases 0-2 landed and closed in v0.10/v0.11;
  the component drawer it reasons about was removed; the attitude readout it
  demands already shipped as the rail row's first tenant.
- "Naming rig actions deletes reference.rs" - false alone; the registry does.
- "ledger_ch3 is generated base content" - it is a hand-written webmod; the
  Sequence rewrite evidence now spans both producers.
- Multi-cell as a straight feature - the one-cell assumption is pervasive
  (wfc `tile()` rejects bodies leaving the unit cell, `SectionExit` is one
  point, `PlacedPart` is one cell); spike-first inside the release.
