# Decide what survives leaving and restarting the open world

- STATUS: OPEN
- PRIORITY: 85
- TAGS: v0.16.0, world, design

## Goal

Design a durable, resumable New Game world: changed sectors survive retirement and game restart, and the player can select a created world through improved Create World and Load/Continue menus. This task decides the state/identity/error contract before implementation (`tasks/20261007-090756/TASK.md`); it does not authorize a save schema or UI code. Seed-only or session-only state is no longer the release target, but is useful comparison evidence.

The owner explicitly wants the seed, visited sectors and their modifications, ships, canisters and other changed world state to survive sector unload/reload and eventual application restart. They suggest keeping the active world's state in memory during play and writing it to disk when leaving; an in-game Save action or additional save points may also be useful, but neither timing nor crash-loss policy is decided. "Visited" must be represented even when the sector has no mutation; whether it means a durable visited-coordinate record or a full cached generated sector is a separate design choice.

The open-world and item-loop work must share the decision. Player inventory exists on live ships, but the lifetime of changed streamed ships, mined rocks, encounters, station state, and future upgrades remains unsettled. M5 trade/mining is being delivered before saves; its session-only limits must be stated rather than implying durable stock, depletion or claim-once loot.

## Agent findings
- `OpenWorldSession` stores a seed; retired cells regenerate pristine content (`crates/nova_world_base/src/lib.rs:18-22,91`). Streamed entities are scenario-scoped but not authored-addressable (`crates/nova_world/src/streaming.rs`). Live ships carry `ShipInventory` (`crates/nova_gameplay/src/inventory.rs`), but there is no ship-mutation save or sector tombstone system.
- Historical `WorldState`, `ShipSource::Persistent`, `SectionModification` and scenario-per-sector sketches in `tasks/20260824-125938/RESEARCH.md` are not implemented and do not decide this format. Platform key-value settings storage is not proof of save-slot capacity/atomicity.

## Read-only Opus scout (2026-10-07, master 0e07c7362)

The research is a proposal, not a save-policy decision. No code, tests or capture ran.

- Create inserts `OpenWorldSession { seed }` and starts Playing (`crates/nova_menu/src/world_setup.rs:216-235`); Retry reloads the scenario (`crates/nova_menu/src/pause.rs:599-620`). Scenario load clears scoped entities (`crates/nova_scenario/src/loader/lifecycle.rs:336-401`). The menu still says that nothing is saved. Returning to the menu does not itself create a save.
- Sector retirement despawns the entire root (`crates/nova_world/src/streaming.rs:870-900`). Deterministic object IDs include cell/name/index (`crates/nova_world/src/generation.rs:494-496`), but are not yet persistent identities across revisions. A looted generated ship's original stock/credits or a mined rock's pristine contents return on revisit; owed ore and mined queues on retired rock children are lost (`crates/nova_scenario/src/mining.rs:806-858`). Loose mined canisters are scenario-scoped rather than children of the sector root (`mining.rs:920-931`); their retirement policy needs an explicit owner. Do not infer item conservation from a sector root alone.
- Jettison removes stock before a canister exists; `CargoIntakeEjectionQueue` temporarily owns it (`crates/nova_ship/src/sections/cargo_intake_section.rs:136-142,503-527`). Runtime canister IDs are not save-stable (`crates/nova_gameplay/src/inventory.rs:617-650`). Player ship state includes inventory/credits, damage and ammunition, not only seed and pose (`crates/nova_gameplay/src/inventory.rs:246-249,351`; `crates/nova_gameplay/src/integrity/carve.rs:184-188`; `crates/nova_ship/src/sections/ammo.rs:262`). A save that omits an in-flight transfer or queue can lose or duplicate stock.
- `nova_assets::persist::load` treats missing, unreadable and corrupt as `None`, while `save` logs failures (`crates/nova_assets/src/persist.rs:36-58`). This best-effort settings API cannot load authoritative worlds. Native `write_atomic` syncs a temp file then renames it (`crates/nova_assets/src/storage.rs:205-250`); web uses localStorage, so capacity, failure visibility and multi-key consistency require a separate contract. A single atomic file is not automatically an atomic world-plus-index update.

**Tier comparison:** Seed-only recreates pristine content and fails the owner's requirement. In-memory sparse deltas repair revisit but fail restart. Durable sparse state (seed, pinned generation/content identity, player record, sector deltas) can meet both, provided each mutation and save boundary has explicit ownership. Storing full generated descriptions instead may permit generator changes but increases schema and storage cost. The scout recommends investigating durable sparse state first; it is not approved.

**Owner decisions to settle before schema or UI work:**
1. Generator/content mismatch: reject and explain (blocks continuation after content updates), store full visited content (larger saves), or migrate with a defined mapping; never silently regenerate changed objects. Specify treatment of missing mods and future RON item IDs together with `20260930-100831`.
2. Rock/ship identity and mutation: tombstone whole source (forfeits remaining ore/stock), replay mined geometry plus saved stock/condition (more exact and version-sensitive), or persist generated state (larger). Decide live-capture-before-retire versus mutation-site recording and check every transfer/destruction path.
3. Loose/queued canisters and jettison during retirement, saving, destroyed intake and restart: persist owned pending stock with stable IDs, or state an explicit loss/refund rule. Session-only loose entities cannot satisfy durable conservation by themselves.
4. Save boundary and Retry: at minimum evaluate a live in-memory world ledger applied on every sector reload, then a disk commit on explicit Save and on Back to Menu/normal exit. If disk writing happens only when leaving, a crash/browser close loses the in-memory session; AppExit alone cannot be assumed to run on every platform. Decide if periodic/checkpoint writes are needed and how a failed departure write blocks or reports the transition. Decide whether Retry loads the last disk save, restarts pristine or is removed from New Game.
5. World list and errors: decide naming, duplicate names, Continue selection, delete/recovery, corrupt/missing/old format, write failure and web space exhaustion. Never fall back from a selected invalid save to a fresh world or overwrite the last valid one without consent. Player death needs a defined resume result.

**Proposed minimal proof slice:** one named world with a visited-coordinate record, the player pose, health, section state, inventory and credits, plus a changed streamed ship, a mined source and a loose/queued canister ownership case, survives both sector retire/revisit and a fresh-app restart. Prove claim-once and stock conservation, missing/corrupt/mismatched-save refusals and interrupted-write recovery; verify pristine cells retain order-independent generation. Use focused codec/ECS tests, deterministic `nova-probe` state assertions and rendered Create/Load/Continue inspection, not exit status alone. These are proof proposals, not authorization to add tests.

**Call-graph delta (proposal):** `Create -> OpenWorldSession(seed) -> LoadScenario -> spawn player; WorldConfig -> generate -> materialize -> retire/despawn` becomes `Create/Load -> validate world header -> load player + deltas -> spawn/restore player; generate -> apply sector deltas -> materialize -> capture before retire -> atomic save at chosen boundary`. Keep save deltas outside `WorldConfig`: changing it currently re-arms/clears the streaming world.

## Proposed design work, not implementation approval

Include each M5 transition: ore-source depletion, mined canister spawn/pickup/destruction, queued jettison cargo ownership, destroyed-ship remaining cargo, market inventory/prices, credits and completed buy/sell. Compare seed-only session, session-only sparse deltas, and durable sparse saves, with one consequence for each.

Distinguish authored/streamed ore bodies and claimed yields, ship/root inventory, loose versus queued canisters, destroyed sources and station market state. Prevent both duplicate reward after retire/revisit and stock loss or duplication during unload/save; define what happens to a queued ejection if its intake is destroyed. Coordinate future mod-item IDs with `tasks/20260930-100831/TASK.md`; item implementation is explicitly last and deferred pending research. Do not assume an item registry or player refits exist while designing a save schema.
- Define failure policy for incomplete writes, invalid content IDs, changed eligible designs, missing mods and version mismatch. Decide save points, world naming/selection, Continue versus Load, Retry semantics, and web storage constraints. Record shared decisions with the implementation task before interfaces are added; do not silently reset or overwrite a world.
- Name the minimum delivery slice that demonstrates claim-once and changed-ship return without a full ECS dump; do not add a schema before owner review.

## Verification to design
- Same seed and visit order variations reproduce pristine cells. A claimed ore body or cargo source cannot reward twice after retire/revisit and restart if the chosen tier promises it. Transfer, jettison queue, loose canister, mining, credits and market stock conserve their owned quantities across unload/save; destroyed stock is lost exactly once. Distinct changes survive or refuse per the selected format. An interrupted write cannot silently replace a prior valid save. Focused pure validation plus deterministic ECS and probe flows; no exit-zero-only proof.
