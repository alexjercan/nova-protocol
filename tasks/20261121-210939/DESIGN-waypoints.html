Nova Waypoints Plan

Pick a found station or a cell on the Map chart, press GOTO, and the HUD shows which way it is: a nav chip with its code and distance in metres, pinned to the screen edge with a chevron when it is off screen. The ship flies there. When the station streams in, the normal GOTO takes over with its real predicted path.

Owner, 2026-11-21: "some kind of waypointing system, so if I want to 'GOTO' a station or sector that is not loaded we should get some kind of 'directional' hint which is the right way". The word "waypointing" explains the need. This plan adds one chip and opens the Map's GOTO on the chart. It adds no panel, bar, or text line.

What happens today

Today you cannot GOTO a station or cell that is not loaded. No code path accepts one, so you get no hint and no error. Paths are at 06813de8d. I read this from the code. I did not run it.

On the HUD

The hint is one nav chip: the target's chart code and the live distance (nova_ui::units::distance, metres below 1 km, else km). It is the beacon chip's shape in nav cyan. The theme sets its corners through chip_node, with no local radius. On screen it stands over the mark. Off screen, or behind the camera, the screen-indicator widget's ClampToEdge pins it 30 px in from the edge and turns the chevron toward the mark. It never breathes or blinks, and it has no other text.

Line and hint stay apart

  • Only FlightPrediction draws a line, in the HUD ribbon and the Map route. The waypoint code draws no stroke anywhere.
  • The hint is a chip and a chevron at one point. It never joins the ship to the mark.
  • Before the first prediction lands there is a chip and no line, the same rule as any GOTO today.
  • The chart view draws no route at all. That is the rule today (scene.rs:672), and it stays.
  • Proof: the existing "no route until the prediction lands" test also runs on a waypoint GOTO, and the example asserts zero visible route strokes while FlightPrediction is absent.

On the Map

What the Map changes

  • Chart GOTO works on a selected Station or Cell mark. Wreck and Job marks keep GOTO hidden, because the owner did not ask for them.
  • A station that is live (in the window) gets a waypoint that is handed over at once: Goto{entity} plus the travel lock.
  • An unloaded station gets GotoPos at its frozen position. A cell gets GotoPos at its centre.
  • Chart Cancel shows while a GOTO flies, the same as in the local view.
  • Destination line (local and chart): GOTO STN-4 128.40 km while a waypoint flies. GOTO LOST stays for a live-entity GOTO that lost its target.
  • Local view: the route draws the GotoPos prediction the same as a GOTO's. The GOTO tag shows only once the target is a plotted contact.
  • Refused GOTO (a fault below): the Map's existing deny cue, and no waypoint.

States

The stage is not stored. It comes from the autopilot: GotoPos means pointed, and Goto on the station means real GOTO. If the autopilot is anything else, the waypoint is cleared. So Cancel, G, STOP, a new GOTO, and a lost ship clear it, and none of those callers needs an edit.

Proposed types and graph

// crates/nova_gameplay/src/waypoint.rs (new): the lowest crate that the HUD,
// the Map, the world crate and the save all reach.

/// What a chart GOTO flies to.
#[derive(Clone, Debug, PartialEq, Eq)]
#[cfg_attr(feature = "serde", derive(serde::Serialize, serde::Deserialize))]
pub enum WaypointTargetType {
    /// A station the chart found, by its generated id.
    Station(GeneratedBodyId),
    /// A cell of the streamed world.
    Sector(SectorCoord),
}

/// On the player ship while a chart GOTO flies. Valid only beside an
/// Autopilot GotoPos (pointed) or a Goto on the entity that wears the
/// station's GeneratedBodyId (handed over); anything else clears it.
#[derive(Component, Clone, Debug, PartialEq)]
pub struct Waypoint {
    pub target: WaypointTargetType,
}

// crates/nova_world_base/src/waypoint.rs (new)
pub enum WaypointFault {
    /// The chart never found this station.
    UnknownStation(GeneratedBodyId),
    /// Found, not live, and no frozen record names it.
    NoFrozenRecord(GeneratedBodyId),
    /// Its cell is live and placed, and it is not there.
    MissingAfterStreamIn(GeneratedBodyId),
}

/// Where a pointed waypoint flies, engine units: the frozen pose of a
/// station, or a cell centre.
pub fn waypoint_mark(
    target: &WaypointTargetType,
    chart: &Chart,
    frozen: &FrozenSectors,
    edge: &ChartSectorEdge,
) -> Result<Vec3, WaypointFault>;

// crates/nova_hud/src/waypoint_chip.rs (new)

Decisions

  1. How an unloaded target is addressed, and where the ID lives.
    • A. WaypointTargetType { Station(GeneratedBodyId), Sector(SectorCoord) } in nova_gameplay, built from the two IDs already in nova_events. Typed and saved as plain data. The HUD can read it.
    • B. Move MapChartMarkType down. It brings Wreck and Job, which are UI selection concepts. A Job does not name one place to fly.
    • C. An EntityId string. Untyped, with a parse at every reader.
    • D. A bare Vec3. It has no identity, so a hand-off is not possible.

    RecommendA. Position source: the frozen ledger record (FrozenSectors), the pose the cell will thaw the station at. Rejected sources: a position copied into ChartStation (a second record that drifts for an orbiting station), regenerating the cell plan (a station layout per request), and the cell centre of id.origin (up to 16 km wrong per axis, the fallback the owner rejects).

  2. Is a cross-sector GOTO flown or only pointed?
    • Flown. The chart GOTO engages GotoPos at the mark. When the station streams in (about 64 km out, its cell enters the window), hand_off_waypoint swaps in Goto{station} and the travel lock. The line is always the real prediction of what the autopilot flies, first to the mark, then to arrival. GOTO means the same thing on every surface. Cost: the player flies GotoPos for the first time, G must toggle it off, and the path changes once at hand-off.
    • Pointed. A waypoint and chip only. You fly by hand. No autopilot change and no line before hand-off. Cost: a GOTO button that does not go, and "arrival" needs a new rule (for example, the waypoint turns into the travel lock when the station streams in, then you press G).

    RecommendFlown. The owner said "GOTO". GotoPos, its prediction, its HUD pip, and its save already exist. This is the decision question for the owner.

  3. What the hint is, when it shows, and when it clears.
    • Look: a nav chip (beacon shape, nav cyan, theme corners) with the code and distance (STN-4 128.40 km, (3, 0, -3) 96.00 km). It is edge-clamped 30 px in, with a chevron, off screen and behind the camera.
    • Shows: from the chart GOTO press, if waypoint_mark is Ok.
    • Hands over: the station entity is live. The chip anchor moves from the point to the entity, and the real GOTO line takes over.
    • Clears: arrival (the autopilot completes), Cancel, G, STOP, a new GOTO, or the ship is lost. The rule is one system: the autopilot no longer matches. A station dies as a body (a derelict), so it is still a valid target. A station that is missing when its cell is placed is a fault.
    • Scope of the chip: (a) only GOTOs that start unloaded; (b) every chart GOTO; (c) every GOTO, radar included.
    • Sector arrival: rest at the cell centre (the GotoPos rule). The other option, STOP on entering the cell, overshoots at cruise speed: braking takes about 80 km on a 160 km leg, and a cell is 32 km.

    RecommendLook and clear rules as above. Chip scope (b): a chart GOTO is a waypoint, and the radar and local GOTO stay as they are. Sector arrival at the centre. The risk that the centre lies in a body is open (see Not verified).

  4. What must fail loudly.
    • Unknown station (not in Chart): error! plus the deny cue from the Map, and a load refusal from a save. The Map offers found stations only, so from the Map this is a defect.
    • No frozen record for a found station that is not live: error! plus the deny cue. No cell-centre fallback.
    • Missing after stream-in: the cell root is live, no PendingSectorStation remains, and no entity wears the id. error!, then remove the autopilot and the waypoint.
    • Reached the mark without a hand-off (a station GotoPos completes): error!. The cell must stream in first.
    • Non-finite mark: refused at resolve. The save already refuses a non-finite GotoPos (controls.rs:243).
    • No ChartSectorEdge (a fixed scene): the chart does not draw, so no GOTO is offered. No silent default edge.

    RecommendAll six, each with a unit test on waypoint_mark or the hand-off system.

Proof plan

Playable example: examples/playable/waypoint_goto_sandbox.rs

It boots the open world through editor_app(true, None) and New Game. It has a hand-run mode with no deadline, and a NOVA_AUTOPILOT=1 walk with assert steps. It adds a README index row.

  1. The start station is found (Chart::station_code is STN-1). Move the ship 4 cells out. Assert that the station entity is gone and that FrozenSectors holds its id.
  2. Open the Map chart, select the STN-1 mark, and press GOTO. Assert Waypoint{Station}, and GotoPos equal to the frozen transform.
  3. Assert that the chip is visible with label STN-1 and a distance. Turn the ship away and assert that the chip is clamped and the chevron is shown and points at the mark's projected side.
  4. Assert that no route stroke and no ribbon segment shows while FlightPrediction is absent.
  5. Fly. On stream-in, assert Goto{station entity}, a travel lock on it, and the chip anchor on Entity.
  6. On arrival, assert that Waypoint is removed, the chip is hidden, and OnGotoComplete carries the station id. Judge the probe timeline markers, not the log.
  7. Second walk: GOTO a cell 3 cells out. It rests at the centre and the waypoint clears.

Unit tests

  • waypoint_mark: an unknown station, a found station with no record, and a cell centre from ChartSectorEdge.
  • clear_stale_waypoint: Cancel, STOP, and a new Goto each remove it. Goto on the station keeps it.
  • Map: chart GOTO is Ready on a Station/Cell mark and Hidden on Wreck/Job. A refused resolve raises the deny cue and sets nothing.
  • Save: a waypoint round-trips. A waypoint that names a station missing from the saved chart is refused.

Frames

One NOVA_CAPTURE=1 frame each: chip on screen, chip clamped off screen, and the chart with the GOTO tag. Lavapipe only, in a sandboxed profile. The owner then plays the hand-run mode.

Not verified

  • Nothing was built or run. "What happens today" is read from the code, not reproduced by a test or a headless run.
  • That every found station out of the window has a FrozenSectors record. Read from frozen.rs and streaming.rs:1175, not tested.
  • Whether an orbiting station thaws where it froze or moves along its orbit. Either way the mark is within its orbit radius, and the hand-off aims at the live body.
  • What GotoPos does when a cell centre lies inside a body (a cluster anchor can sit near a cell centre). NoSafeLeg would log an error and disengage. The example's second walk must find out.
  • Whether station marks more than 3 cells out are selectable in the chart. The marks draw at any cell (chart.rs:662-701), but the grid is 7 by 7.
  • That a New Game's start station is in the chart at the first frame.
  • No compiled check of the proposed types. The waypoint is a component on the player ship, not a world entity, so nova_world freeze and adoption never see it (adoption rules not read in full).

Decision for you

Should a GOTO on an unloaded station fly the ship there, with the autopilot heading for the station's last known position and the normal GOTO with the real path taking over when the station streams in? Or should it only point the way while you fly by hand?
