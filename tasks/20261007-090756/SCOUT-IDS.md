# ID and detached-entity scout

Read-only source map for the `resumable-worlds` checkout. No Rust source was changed. No Cargo command was run.

## 1. `EntityId` coverage and uniqueness

- Open-world player root: yes, ID `player`. Streamed sector roots and their described asteroids use `base_scenario_object`; generated ship roots use it too. `base_scenario_object` inserts `EntityId` (`crates/nova_authoring/src/base_content/scenarios/open_world.rs:29,59`; `crates/nova_world/src/streaming.rs:211-269,381-421`; `crates/nova_scenario/src/actions/spawn.rs:103-117`). Carved islands are separate `CarvedChunk`s and `spawn_carved_chunk` assigns no `EntityId` (`crates/nova_scenario/src/objects/asteroid_carve.rs:559-568`; `crates/nova_gameplay/src/integrity/chunk.rs:232-254`).
- Generated IDs are unique across the live generated window: `sector_id` prefixes IDs with the coordinate slug and manifest validation rejects duplicate IDs within a cell (`crates/nova_world/src/generation.rs:508-510,587-593`; `crates/nova_world/src/lib.rs:347-355`). Generated ship candidates use that function (`crates/nova_world_base/src/clusters.rs:1547-1554,1590-1620`). The fixed player ID does not share the `sector_...` prefix (`crates/nova_authoring/src/base_content/scenarios/open_world.rs:29,59`).
- Every spawned ship section gets an `EntityId` from its design-local `section.id`; that is not a world-unique ID. Generated layouts reuse slot-derived names such as `weapon_{slot}` and `{slot}_starboard` / `{slot}_port` across ships (`crates/nova_scenario/src/objects/spaceship.rs:910-915`; `crates/nova_world_base/src/ship_layout.rs:1657-1677,2002-2008,2064-2075`).
- Fixtures do not get `EntityId`. Both the plate and decor bundles carry `SectionFixture` and their kind marker, but no ID (`crates/nova_ship/src/sections/shell_skin.rs:642-654`; `crates/nova_ship/src/sections/skin_decor.rs:575-588`).
- A frozen body's ID is optional. Freeze copies an ID only if present; the public contract names severed wrecks and canisters as ID-less (`crates/nova_world/src/frozen.rs:310-312,358-360,471`).

## 2. `EntityId` to live `Entity`

- There is no global ID index or universally unique lookup. `scoped_entities` queries live entities with both `ScenarioScopedMarker` and `ScenarioAddressableMarker`, then matches `EntityId`; it deliberately returns multiple matches. `scoped_entity` returns the first (`crates/nova_scenario/src/actions/mod.rs:78-106`). Streamed sector entities are explicitly scoped but not addressable (`crates/nova_world/src/streaming.rs:183-190`).

## 3. Rebuilding one detached section's art

- `section_body` is the existing config-to-section factory. It rebuilds base and kind components from `SectionConfig`; render observers then build kind-specific art. `thaw_section` restores health and other saved section state (`crates/nova_ship/src/sections/base_section.rs:559-597`; `crates/nova_ship/src/sections/frozen.rs:187-208,270-290`).
- This is not a standalone art-only rebuild. Whole-ship skin is derived from all sibling sections' structure and the parent `ShipStyle`/`GameStyles`; the style palette supplies plate colors. Wreck thaw therefore restores the saved parent style and each section's config, pose, state, neighbors, and fixtures (`crates/nova_ship/src/sections/shell_skin.rs:702-760,778-801,1050-1090`; `crates/nova_ship/src/sections/skin_style.rs:72-106`; `crates/nova_ship/src/sections/integrity.rs:168-180,203-255,259-289`).
- There is no separate per-section hull-color input to `section_body`; plate color comes from the ancestor style. Ship section damage effects do not carve section geometry; they are materials or particles. Restored section health re-derives `DamageLevel` (`crates/nova_ship/src/sections/base_section.rs:559-597`; `crates/nova_ship/src/sections/shell_skin.rs:1050-1090`; `crates/nova_ship/src/sections/damage_effects.rs:39-44`; `crates/nova_ship/src/sections/frozen.rs:209-220`).

## 4. Fixture reconstruction and detachment

- A dead fixture is the same entity, detached from `ChildOf` and `Collider`; its transform, art, and children stay. Nested greeble colliders are recursively removed. No mesh is rebuilt during shedding (`crates/nova_ship/src/sections/fixture.rs:179-184,197-213,303-355`).
- Durable reconstruction is supported by the frozen-section path: plates save shape/pose/health; decor saves name/model/collider size/pose/health; children are captured recursively and rebuilt through `frozen_plate_body` / `frozen_decor_body` (`crates/nova_ship/src/sections/frozen.rs:111-151,153-159,225-244`; `crates/nova_ship/src/sections/shell_skin.rs:666-681`; `crates/nova_ship/src/sections/skin_decor.rs:596-618`). Fresh decor placement still depends on the full ship skin/style pass (`crates/nova_ship/src/sections/shell_skin.rs:702-760,778-801`).

## 5. Asteroid carved islands

- A severed island at or above `CHUNK_MIN_VOLUME` is meshed from its own `SignedField`, recentered, and paired with a collider. Smaller islands become dust (`crates/nova_scenario/src/objects/asteroid_carve.rs:495-520,574-606`; `crates/nova_gameplay/src/integrity/chunk.rs:44-51`). The parent asteroid's material is reapplied to each spawned rock piece (`crates/nova_scenario/src/objects/asteroid_carve.rs:559-578`).
- The mesh is data-dependent (`island.surface().build()`); there is no fixed vertex-count target or typical count in this path. **Unverified:** representative vertices per chunk require runtime meshes and were not measured.
- These are collision bodies, not durable asteroids: `spawn_carved_chunk` gives a chunk a mesh, `ChunkGrace`, and a 30-second `TempEntity`, but no `Health`, `DamageMarks`, or `AsteroidField` (`crates/nova_gameplay/src/integrity/chunk.rs:126-130,232-254`; `crates/nova_scenario/src/objects/asteroid_carve.rs:495-520`).
- By contrast, a frozen asteroid retains kind, texture, seed, damage marks, and optional carved field; the field snapshot retains the signed field and remesh bookkeeping, then rebuilds mesh/collider (`crates/nova_scenario/src/objects/asteroid.rs:445-470`; `crates/nova_scenario/src/objects/asteroid_carve.rs:244-292`). Thaw rendering builds a fresh surface material from its texture/kind/seed and selects the thawed carved mesh (`crates/nova_scenario/src/objects/asteroid.rs:787-843`).

## 6. Torpedo launch refs, writers, and readers

- Bay launch sets `ProjectileOwner(shooter)`, `TorpedoSectionPartOf(section)`, and `TorpedoSectionSpawnerEntity(spawner)`. It does not set `TorpedoTargetPosition`. After spawning, it inserts `TorpedoWeave` with phase derived from the projectile's `Entity` (`crates/nova_ship/src/sections/torpedo_section/bay.rs:359-405,544-559`).
- `TorpedoWeave` is mutated by `torpedo_terminal_weave`; that system requires a target position. `update_target_position` is the runtime writer of `TorpedoTargetPosition`, inserting it only after lock and then updating it (`crates/nova_ship/src/sections/torpedo_section/mod.rs:662-665,716-744`; `crates/nova_ship/src/sections/torpedo_section/projectile.rs:12-54,495-521`). The position is read by PN guidance, terminal weave, detonation, and probe snapshots (`crates/nova_ship/src/sections/torpedo_section/projectile.rs:230-281,395-430,495-521`; `crates/nova_probe/src/capabilities/snapshot.rs:1627`).
- `TorpedoTargetEntity` is committed by player, AI, and scripted targeting; the choice is launch-time and not replaced (`crates/nova_ship/src/input/player/intent.rs:223-253`; `crates/nova_ship/src/input/ai/torpedo.rs:204-244`; `crates/nova_ship/src/sections/torpedo_section/scripted.rs:45-75`; `crates/nova_ship/src/sections/torpedo_section/mod.rs:646-658`). Sensor, AI acquisition, and point-defense readers also inspect it (`crates/nova_ship/src/input/targeting/sensing.rs:158-307`; `crates/nova_ship/src/input/ai/acquisition.rs:270-312`; `crates/nova_ship/src/input/point_defense/assignment.rs:156-211`).
- If the target dies, tracking removes its stale entity link and leaves the last `TorpedoTargetPosition`; guidance uses zero target velocity and detonation may still fuse against that saved point. Never-locked torpedoes have no position and fly straight (`crates/nova_ship/src/sections/torpedo_section/projectile.rs:18-54,276-281,399-430`; `crates/nova_ship/src/sections/torpedo_section/mod.rs:662-665`).
- `TorpedoSectionPartOf` is used by bay/scripted lifecycle, detonation (copied to the blast), and projectile/blast rendering. A dead section does not stop in-flight guidance/fuzing; it can suppress section-derived blast art (`crates/nova_ship/src/sections/torpedo_section/bay.rs:178-220`; `crates/nova_ship/src/sections/torpedo_section/scripted.rs:45-75`; `crates/nova_ship/src/sections/torpedo_section/projectile.rs:230-243,313-326`; `crates/nova_ship/src/sections/torpedo_section/render.rs:22-29,514-535`).
- `TorpedoSectionSpawnerEntity` is read for launch VFX and launch SFX. A dead spawner makes those optional cues return without emitting; it does not remove the already-launched projectile (`crates/nova_ship/src/sections/torpedo_section/render.rs:807-844`; `crates/nova_ship/src/ship_audio/combat.rs:290-344`).
- `ProjectileOwner` is read for live-launcher arming, launch effect velocity, damage attribution, collision-owner filtering, and projectile party/relation classification. If the owner dies, arming treats the launcher as absent; launch flash falls back to zero inherited velocity. The torpedo copies `Allegiance` at launch, so party classification survives owner death, but an owner-based retaliation lookup no longer has a live ship. If the owner dies before player/AI target commitment, those owner lookups skip and leave the torpedo unchosen (`crates/nova_ship/src/input/player/intent.rs:220-253`; `crates/nova_ship/src/input/ai/torpedo.rs:176-244`). Collision filtering cannot match the dead owner's body (`crates/nova_ship/src/sections/torpedo_section/projectile.rs:62-88`; `crates/nova_ship/src/sections/torpedo_section/render.rs:811-844`; `crates/nova_ship/src/sections/torpedo_section/bay.rs:544-550`; `crates/nova_ship/src/input/ai/threat.rs:154-183`; `crates/nova_gameplay/src/projectile_hooks.rs:46-75`; `crates/nova_gameplay/src/relations.rs:115-145`; `crates/nova_ship/src/input/targeting/sensing.rs:307`; `crates/nova_ship/src/input/point_defense/assignment.rs:211`; `crates/nova_ship/src/input/ai/acquisition.rs:312`; `crates/nova_hud/src/edge_indicators.rs:322`).

## 7. Turret projectile refs and dead targets

- A bullet stores `TurretSectionPartOf(turret)`, `TurretSectionMuzzleEntity(muzzle)`, and `ProjectileOwner(ship)` (`crates/nova_ship/src/sections/turret_section/firing.rs:335-356`). `TurretSectionPartOf` keys the fire-SFX lookup; a despawned turret has no sound component, so the observer returns silently (`crates/nova_ship/src/ship_audio/combat.rs:242-267`).
- The muzzle-flash observer resolves the muzzle transform and its effect. If the muzzle is gone, it logs and returns; if the owner is gone, it uses zero ship velocity. A dead muzzle encountered before firing is logged and that muzzle's shot is skipped (`crates/nova_ship/src/sections/turret_section/render.rs:15-70,110-123`; `crates/nova_ship/src/sections/turret_section/firing.rs:184-202`).
- `ProjectileOwner` also feeds the swept-round owner filter; a stale owner handle resolves to no owner collider and does not suppress any collision. Turret projectiles copy allegiance, preserving party data after owner death (`crates/nova_gameplay/src/rounds.rs:328-331,1178-1204`; `crates/nova_ship/src/sections/turret_section/firing.rs:386-395`). Probe snapshots read the muzzle and owner refs diagnostically (`crates/nova_probe/src/capabilities/snapshot.rs:1388,1583`).

## 8. `TempEntityState`

- Gameplay initializes the private state from `TempEntity` and only `update_temp_entities` mutates it, by `Timer::tick(time.delta())`; finished timers despawn the entity (`crates/nova_gameplay/src/lifetime.rs:72-123`). Probe snapshots read remaining lifetime (`crates/nova_probe/src/capabilities/snapshot.rs:1618`).
- No Rust source calls `Timer::set_elapsed`; `TempEntityState`'s elapsed time advances through `tick`, not an external `DerefMut` elapsed-time write (`crates/nova_gameplay/src/lifetime.rs:72,117-123`).

## 9. Resume and full-window materialization

- There is no readiness resource/state for “all desired sectors and their frozen bodies are live.” `ReadySectors` means prepared, not spawned; `SectorJobStats.materialized` is an app-lifetime total, not a live gauge (`crates/nova_world/src/streaming.rs:579-581,640-656`).
- Resume inserts `ResumedWorld`; `restore_resumed_world` restores the ledger on the world-arming frame, after Cleanup and before Observe. Preparation is asynchronous and `materialize_ready_sector` spawns at most one desired sector per Update (`crates/nova_world_base/src/save/session.rs:208-230,252-268`; `crates/nova_world_base/src/lib.rs:178-193`; `crates/nova_world/src/streaming.rs:814-850`).
- The nearest signal is a debug log, not a state. It checks that all *other* desired coordinates were already live and treats the just-selected coordinate as live before its deferred spawn commands have applied (`crates/nova_world/src/streaming.rs:814-879`). The actual all-live condition first holds after the final desired sector's spawn/thaw commands apply; async preparation determines which frame that is. **Unverified:** no runtime trace was collected to measure that frame.
- The scenario loading screen and `ScenarioLoadGate` wait only for `NovaEventWorld::is_settling()` and optional `ScenarioPreload::is_pending()`, plus screen dwell rules; neither checks the streaming window (`crates/nova_scenario/src/world.rs:72-77`; `crates/nova_core/src/loading_screen.rs:418-452`; `crates/nova_scenario/src/loader/gate.rs:90-106`). Those conditions release physics and virtual clocks before the dynamic window is full, so simulation can run while further sectors prepare/materialize (`crates/nova_scenario/src/loader/gate.rs:82-106`; `crates/nova_world/src/streaming.rs:814-850`).
