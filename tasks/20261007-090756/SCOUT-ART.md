# Detached-piece art source map

This adds art-record and thaw facts to `SCOUT-PIECES.md`; it does not repeat its per-kind tree. Claims cover Nova-authored nodes. **Unverified** marks limits not established by source inspection. Paths are relative to the worktree unless marked external.

## 1. `WorldAssetRoot`

- Bevy 0.19's `WorldAssetRoot` is a component tuple with exactly `Handle<WorldAsset>`; it also requires `Transform` and `Visibility`. It has no `AssetRef` or path field. [external: `/home/alex/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/bevy_world_serialization-0.19.1/src/components.rs:13-28`]
- Nova's `AssetRef<A>` is `Path(String)` or `Handle<A>` and `path()` is `None` for handle-backed refs. A normal section render observer resolves its config ref and puts only the handle into `WorldAssetRoot`; the original `SectionBuildConfig` stays on the section detach despawns. [crates/nova_gameplay/src/asset_ref.rs:29-35,95-115; crates/nova_ship/src/sections/hull_section.rs:105-127; crates/nova_ship/src/sections/base_section.rs:534-564; crates/nova_gameplay/src/integrity/explode.rs:461-477]
- The component-bearing wrapper is the scene instancer, not a separate `SceneRoot` node: `spawn_as_child` attaches a world-asset instance below it. Preserve the wrapper as a section-authored node; exclude its spawned child subtrees from node records, because thawing its asset re-derives those descendants. [external: `/home/alex/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/bevy_world_serialization-0.19.1/src/components.rs:18-24`; `/home/alex/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/bevy_world_serialization-0.19.1/src/world_asset_spawner.rs:192-205,687-717`]
- Capture can identify that subtree by the `WorldAssetRoot` wrapper boundary (and its `WorldInstance` component after spawning); do not classify the wrapper itself as imported scene content. [external: `/home/alex/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/bevy_world_serialization-0.19.1/src/components.rs:18-28`; `/home/alex/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/bevy_world_serialization-0.19.1/src/world_asset_spawner.rs:685-715`]
- There is a ready event: `WorldInstanceReady { entity, instance_id }` fires on the instance parent after spawning. For a `WorldAssetRoot`, that parent is the wrapper. [external: `/home/alex/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/bevy_world_serialization-0.19.1/src/world_asset_spawner.rs:28-40,522-535`]

## 2. Section animation

- `resolve_section_animation_rigs` walks descendants, reads `Name` and `Transform`, and matches `name.as_str().starts_with(track.config.node_prefix)`; this is name-prefix lookup, not a path lookup. It records `TrackNode { entity, rest, slat }` and writes the track pose to the matched Transform. [crates/nova_ship/src/sections/section_animation.rs:214-242,443-491]
- `SectionAnimations` and its tracks live on the section. The rig resolver and driver require that component; after the source section is despawned, its track config/progress/targets and entity handles are gone, while the last values written into surviving node `Transform`s remain. [crates/nova_ship/src/sections/section_animation.rs:264-267,443-570; crates/nova_gameplay/src/integrity/explode.rs:470-477]
- A thaw can reapply captured transforms after `WorldInstanceReady` by matching saved hierarchy/Names to re-derived scene nodes. The existing lookup function is `resolve_section_animation_rigs`, but it is not an art-only restore API: it requires `SectionAnimations` on a section ancestor and applies track progress, not captured per-node transforms. [crates/nova_ship/src/sections/section_animation.rs:412-491]

## 3. Damage cracks

- `DamageCracks` is the section-level opt-in. Rendered `MeshMaterial3d<StandardMaterial>` meshes below it receive `PendingSectionCracks { section: Entity }`, then `SectionCracks { section, source: Handle<StandardMaterial>, bucket, material }`; neither source material path nor durable material key is stored there. [crates/nova_ship/src/sections/damage_cracks.rs:151-176,234-238,320-355]
- Missing owner section means fully damaged bucket `SECTION_CRACK_BUCKETS - 1` (bucket 7 of 8). Pending resolution rebuilds the cracked material from the source StandardMaterial handle, installs `MeshMaterial3d<SectionCracksMaterial>`, removes the StandardMaterial and pending marker. Settled orphan `SectionCracks` markers are removed while the cracked material remains. [crates/nova_ship/src/sections/damage_cracks.rs:79-95,363-425,433-499]
- There is no thaw-facing API accepting a bucket: `PendingSectionCracks` is private and has only `section: Entity`. Its resolver treats a missing section as max damage, so code inside this module could reuse that behavior after source material resolution; source scan found no section-free constructor. [crates/nova_ship/src/sections/damage_cracks.rs:234-238,363-425]

## 4. `PlaceholderArt`

- The resource has five mesh handles (`body`, `window`, `barrel`, `nozzle`, `turret_plate`) and five StandardMaterial handles (`structure_material`, `controller_material`, `window_material`, `nozzle_material`, `turret_plate_material`); `FromWorld` builds one shared set. It defines no closed enum or stable key for a placeholder node. [crates/nova_ship/src/sections/placeholder_art.rs:54-75,77-108]
- Existing branch choices: hull, railgun, docking and torpedo bodies use `body + structure_material`; controller uses `body + controller_material` and `window + window_material`; thruster uses `barrel + structure_material` and `nozzle + nozzle_material`; an unmeshed structural turret joint uses `turret_plate + turret_plate_material`. [crates/nova_ship/src/sections/hull_section.rs:105-127; crates/nova_ship/src/sections/railgun_section/render.rs:193-210; crates/nova_ship/src/sections/docking_section/render.rs:35-53; crates/nova_ship/src/sections/torpedo_section/render.rs:43-67; crates/nova_ship/src/sections/controller_section.rs:640-663; crates/nova_ship/src/sections/thruster_section.rs:775-793; crates/nova_ship/src/sections/turret_section/render.rs:294-359]
- Placeholder visual components carry mesh/material handles beside ordinary Name/Transform; those handles are not durable art IDs. Names distinguish current branches in source, but there is no closed runtime key. [crates/nova_ship/src/sections/placeholder_art.rs:54-75; crates/nova_ship/src/sections/hull_section.rs:120-127]

## 5. Thruster exhaust

- The named outer `Thruster Exhaust` child carries `SectionRenderOf`, `ThrusterExhaustConfig`, `ThrusterExhaustPlume`, `Mesh3d` and `MeshMaterial3d<ThrusterPlumeMaterial>`; the inner child carries `ThrusterExhaustPlume`, `Transform`, `Mesh3d` and the same material type, but no durable config of its own. `ThrusterExhaustConfig` records geometry, extents, heights, intensities and colors; its observer builds both meshes/materials. [crates/nova_ship/src/sections/thruster_section.rs:800-812,814-894]
- `ThrusterExhaustPlume` carries private `spec` and `bucket`; the update searches ancestors for a live thruster, sets wanted throttle to zero when none exists, and swaps both cones to the zero bucket. `DamagePlume` and input are section-level state, not the exhaust's durable config. [crates/nova_ship/src/sections/thruster_section.rs:634-696; crates/nova_ship/src/sections/damage_plume.rs:57-63]
- Thus a detached exhaust settles dark/idle after its update; current bucket/handles are runtime state, while `ThrusterExhaustConfig` is enough to regenerate geometry/material parameters. [crates/nova_ship/src/sections/thruster_section.rs:641-696,814-894]

## 6. Skin plate surfaces

- A `SkinSurfaceMarker` child has `Name("Skin Surface")`, `ChildOf(plate)`, `Mesh3d` and `MeshMaterial3d`; the marker is unit-shaped and carries no surface index or role. The plate's `ShipSkinMarker(ShellShape)` is the durable shape input. [crates/nova_ship/src/sections/shell_skin.rs:626,1085-1110]
- `SkinAssets::surfaces(shape, style: Option<&ShipStyleConfig>, ...)` uses `ShellShape::surfaces()` to build all nonempty `(ShellSurface, Mesh)` entries and caches materials by style id and role. `hang_surfaces` rebuilds all children, not one selected role. A single-node rebuild by `(shape, role/index, style id)` has no existing entry point; the available functions rebuild the complete surface set after resolving the style config. [crates/nova_ship/src/sections/shell_shape.rs:466-518; crates/nova_ship/src/sections/shell_skin.rs:995-1035,1050-1110]
- Durable style key type is `ShipStyle(pub Option<String>)`, not a new ID type; it lives on the ship root. `GameStyles::get_style(&str)` resolves it. A detached plate has shape but not that ancestor style. [crates/nova_ship/src/sections/skin_style.rs:559-585; crates/nova_ship/src/sections/shell_skin.rs:1050-1086,1113-1128]

## 7. Particle-effect children

- Turret muzzle effect child components: `Name`, `TurretSectionBarrelMuzzleEffectMarker`, `ParticleEffect`, `EffectProperties`, and fallback-only `EffectMaterial`. The effect `AssetRef<EffectAsset>` is on its parent muzzle joint in `TurretSectionBarrelMuzzleEffect`; the child has only a resolved effect handle. [crates/nova_ship/src/sections/turret_section/mod.rs:294-297,341-344; crates/nova_ship/src/sections/turret_section/render.rs:664-712]
- Torpedo launch child components: `Name`, `TorpedoSectionSpawnerEffectMarker`, `ParticleEffect`, `EffectProperties`. Its parent's `TorpedoSectionSpawnerEffect` carries `Option<AssetRef<EffectAsset>>` (`None` selects the default); the child has only a handle. [crates/nova_ship/src/sections/torpedo_section/mod.rs:617-640; crates/nova_ship/src/sections/torpedo_section/render.rs:759-800]
- Hanabi adds `EffectSpawner` at runtime beside `ParticleEffect`; both built-in effects set `with_emit_on_start(false)` and projectile-added observers call `EffectSpawner::reset()`. A detached piece has no live section fire path. **Unverified:** authored `EffectAsset` spawners may emit on start or retain particles already emitted; Nova accepts authored assets and does not force their emission settings. [external: `/home/alex/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/bevy_hanabi-0.19.0/src/spawn.rs:924-998`; crates/nova_ship/src/sections/turret_section/render.rs:546-553,664-712; crates/nova_ship/src/sections/torpedo_section/render.rs:667-685,759-800]
- Source scan found other Hanabi effects only as torpedo blast/projectile effects and railgun wakes spawned on projectile entities, not children of a detached static section tree. [crates/nova_ship/src/sections/torpedo_section/render.rs:514-591; crates/nova_ship/src/sections/railgun_section/wake.rs:265-285]

## 8. Railgun charge glow

- `Railgun Charge Glow` carries `RailgunChargeGlowMarker`, identity `Transform`, `Visibility::Hidden`, and `PointLight { color: Color::srgb(0.45, 0.85, 1.0), intensity: 0, range: 20.0, radius: 0, shadow_maps_enabled: false }`. [crates/nova_ship/src/sections/railgun_section/render.rs:49-60,214-245]
- The live driver sets position to `muzzle_offset * progress`, intensity to a power curve, and visibility to inherited iff progress is positive. When the section is gone, the child is no longer visited, so its last light/pose freezes: normally hidden and dark, or visibly stuck at the last charge if detached mid-charge. [crates/nova_ship/src/sections/railgun_section/render.rs:259-291; crates/nova_gameplay/src/integrity/explode.rs:461-477]

## 9. `ChunkGrace` collider

- `detach_destroyed_body` clones the dying entity's actual avian `Collider` into `ChunkGrace::new(collider, clearance)`; it does not reconstruct that field from the `SectionCollider` config at detach. For a normal section, `base_section` derives the avian collider from `SectionCollider::to_collider()` first. [crates/nova_gameplay/src/integrity/explode.rs:175-203,349-350,410-445; crates/nova_ship/src/sections/base_section.rs:54-95,618-647]
- `ChunkGrace` has private `collider` and `remaining` fields and no serde derive. `SectionCollider` does have a serde derive behind Nova's `serde` feature; avian `Collider` derives serde only behind avian's `serialize` feature. Nova's direct avian dependencies do not request `serialize`; Cargo feature unification is **unverified** (Cargo was prohibited). [crates/nova_gameplay/src/integrity/chunk.rs:173-195; crates/nova_ship/src/sections/base_section.rs:54-55; crates/nova_gameplay/Cargo.toml:10,44; crates/nova_ship/Cargo.toml:10,46; external: `/home/alex/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/avian3d-0.7.0/src/collision/collider/parry/mod.rs:366-380`; `/home/alex/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/avian3d-0.7.0/Cargo.toml:97-105`]

## 10. Detached-tree component inventory

Scope: components Nova directly adds to the piece root and source-created descendants. **Unverified / not closed:** arbitrary referenced world assets can add asset-specific components; Bevy/Avian required and runtime-generated components also depend on engine/plugin setup. [external: `/home/alex/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/bevy_world_serialization-0.19.1/src/components.rs:18-28`; crates/nova_ship/src/sections/hull_section.rs:105-127; crates/nova_gameplay/src/integrity/explode.rs:420-477]

- **Common node fields / art:** capture parent topology (currently `ChildOf`/`Children`) as indices plus `Name`, local `Transform`, and `Visibility`. Standard section render wrappers have `SectionRenderOf` plus `WorldAssetRoot` or placeholder `Mesh3d`/`MeshMaterial3d<StandardMaterial>`. Bevy adds `WorldInstance` as runtime instance bookkeeping on a loaded wrapper; regenerate it, do not persist it. [crates/nova_gameplay/src/integrity/explode.rs:450-477; crates/nova_ship/src/sections/hull_section.rs:105-127; external: `/home/alex/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/bevy_world_serialization-0.19.1/src/components.rs:18-28`; `/home/alex/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/bevy_world_serialization-0.19.1/src/world_asset_spawner.rs:685-716`]
- **Other art inputs/state:** turret joint nodes retain `TurretJointRenderMesh(Option<AssetRef<WorldAsset>>)` and `TurretJointRenderMeshTransform`; decor roots retain `ShipDecorMarker(AssetRef<WorldAsset>)`, `DecorColliderSize`, and receive `WorldAssetRoot` on that same entity. Scene meshes can carry `PendingSectionCracks`/`SectionCracks` and cracked-material handles; skin plates/surface markers and exhaust/glow/effect types are listed above. Hanabi also adds runtime `EffectSpawner` beside each `ParticleEffect`. Runtime handles/buckets are not durable IDs. [crates/nova_ship/src/sections/turret_section/mod.rs:222-228; crates/nova_ship/src/sections/turret_section/setup.rs:53-55; crates/nova_ship/src/sections/skin_decor.rs:557-585,639-652; crates/nova_ship/src/sections/damage_cracks.rs:151-176,234-238,363-425; external: `/home/alex/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/bevy_hanabi-0.19.0/src/spawn.rs:924-998`]
- **Fixture gameplay to omit:** plate/decor nodes carry `SectionFixture` (which requires `HealthIsolated`), `Health`, and `ColliderDensity`; a spent fixture can carry `HealthZeroMarker`, then the shed system drops its `ChildOf` and it leaves this piece tree. 1. World scene wrapper: rebuild by `WorldAssetRoot` today; gap: only Handle remains, so persist original `AssetRef`/path. [external: `/home/alex/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/bevy_world_serialization-0.19.1/src/components.rs:18-28`; crates/nova_ship/src/sections/hull_section.rs:105-127]

4. Placeholder meshes: resource can spawn each visual today; gap: no durable per-node key, only shared runtime handles. [crates/nova_ship/src/sections/placeholder_art.rs:54-108]
5. Cracked meshes: orphan path can make bucket 7 from source material; gap: pending type is private, has no bucket, and source is only a Handle. [crates/nova_ship/src/sections/damage_cracks.rs:155-176,234-238,363-425]
6. Skin surfaces: `SkinAssets::surfaces` rebuilds the full shape/style set; gap: surface child has no role key and plate loses ship-root `ShipStyle`. [crates/nova_ship/src/sections/shell_skin.rs:995-1035,1085-1110; crates/nova_ship/src/sections/skin_style.rs:575-585]
7. Skin decor: `ShipDecorMarker` retains an AssetRef and its observer resolves it; gap: omit Health/physics and preserve style-derived pose/name separately. [crates/nova_ship/src/sections/skin_decor.rs:557-585,639-652]
8. Thruster exhaust: retained `ThrusterExhaustConfig` supplies generation inputs; gap: no durable material handle and detached system settles plume to bucket zero. [crates/nova_ship/src/sections/thruster_section.rs:151-184,641-696,814-894]
