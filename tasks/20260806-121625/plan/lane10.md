## 3. The `Storage` trait

Mirrors the existing `PortalTransport` pattern - the crate already knows this
shape.

```rust
// NEW  crates/nova_assets/src/storage.rs
/// Persistent key-value storage, one impl per platform. Mirrors
/// PortalTransport: the trait exists so the call sites stop carrying
/// #[cfg(target_arch = "wasm32")] and so a test can substitute a fake.
pub trait Storage: Send + Sync + 'static {
    fn read(&self, key: &str) -> Option<Vec<u8>>;

    /// MUST be atomic: temp file + fsync + rename on native, a single
    /// set_item on wasm. A kill mid-write leaves the previous value intact.
    /// This is the contract F07 introduces - see lane03.md.
    fn write(&self, key: &str, bytes: &[u8]) -> Result<(), StorageError>;

    fn remove(&self, key: &str) -> Result<(), StorageError>;
}

pub struct NativeStorage { root: PathBuf }   // NEW
pub struct WebStorage;                        // NEW - localStorage
```

**Sequencing with L3, and it matters.** F07's atomic-write helper touches
`persist.rs:91`, `mod_cache.rs:521`, `portal/catalog.rs:197` and
`bin/content.rs:103` - **the same four files this trait extracts.** Land F07 as
the change that *introduces the trait's `write`*, then this lane extends the
trait to cover the read side and the wasm backend. A free helper in L3 that L10
then absorbs means writing the same four call sites twice.

`persist.rs` already splits `mod backend` by `#[cfg(target_arch = "wasm32")]`
(native at `:75-98`, wasm below), so the two impls exist - they just are not
behind a trait.

**Do not re-argue this from bit-rot.** The wasm-rot prediction was
**withdrawn** (W3): all 14 crates type-check clean on `wasm32-unknown-unknown`.
The trait is justified by testability and by deleting the cfg gates, which is a
narrower but sufficient case.

scenario-observable moments, not because of a blanket rule.
